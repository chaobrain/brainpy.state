### 2.1 The one failure in the first full run

`validation/g2_brunel_nest_test.py::test_g2_runs_are_in_the_asynchronous_irregular_regime`
— a sanity check written in T10, not a gate criterion — asserted CV-ISI > 0.3. Both
NEST and the kernel give 0.083 at the NEST example parameters (a regular oscillatory
state). The test's assumption was wrong, not the simulation. It was renamed
`test_g2_runs_are_in_the_expected_firing_regime` and given bounds that match the measured
regime on both sides. The gate-suite run above (179 passed) includes the fix, and so
does the final re-run (section 8).

## 4. G9 benchmark

Protocol (`benchmarks/g9_interleaved.py`, user decision 2026-10-22). Only the CPU is
measured; the GPU is skipped by user decision. No load-average gate. A core is chosen
whose CPU and hyperthread sibling are both < 5 % busy (from `/proc/stat` over 5 s):
**core 2, sibling 3, both 0.0 %**. Every run is pinned with `taskset -c 2`. Runs
alternate old `Simulator` (T0 script) and K0 kernel in fresh processes, 3 rounds per
configuration, using the T0 measurement protocol inside each process. Before each run the
core is re-sampled, and the driver waits while it is busy. During each run the sibling
must stay < 5 % busy and the child must get ≥ 85 % of the core; otherwise the run is
discarded and redone. All 24 runs were valid on the first attempt (core share ≥ 0.999,
sibling ≤ 0.01 % busy). Load average 2.98–3.90 during the session, from the user's jobs
on other cores.

Host `wanglab3090b-01a0` (i7-14700KF), commit `d8dccce`, `JAX_PLATFORMS=cpu`, jax 0.12.0,
brainevent 0.2.1, brainstate 0.6.0, numpy 2.5.4.

```bash
/tmp/k0/remote.sh T10 'python benchmarks/g9_interleaved.py run --commit d8dccce --rounds 3' > g9.log
python benchmarks/g9_interleaved.py compare g9.log --out benchmarks/results/2026-10-22-T10-g9-interleaved.json
```

* Compile time: the kernel takes 1.4–1.7 s against about 1.0 s for the old `Simulator`.
  This is reported, not gated.
* Peak RSS at f64, order 2500, is 0.9 % above the old `Simulator`. The kernel's runtime
  arrays are smaller, but the RSS is dominated by the Python/JAX runtime (about 0.7 GiB).
* Before the T10 optimisations, the kernel at order 2500 f32 measured 0.86–0.89 ms/step
  and 1.96 GiB, i.e. 1.27× and 1.27× the old `Simulator` (local, pinned) — a G9 fail.
  Three contained `_kernel` changes, each tested, fixed this:
  1. Storage structure arrays became jit arguments instead of closed-over HLO constants.
  2. A gather path for `one_to_one` and small CSR projections.
  3. An inversion Poisson sampler.

  See [T10 spec §3](2026-10-22-k0-t10-gates.md).

## 5. Decisions taken during K0

| task | decision |
|---|---|
| T0 | Baseline on the remote host only; CPU rows unpinned and pinned (`taskset -c 4`); GPU float64 with the default brainevent backend aborts (upstream bug), so a second GPU sweep with `--brainevent-backend cusparse` supplies the float64 GPU reference. `poisson_generator` gets a finite `stop` (default `inf` overflows without x64). |
| T2 | JAX propagators return the mathematically correct value where the old NumPy `alpha_propagator_p31_p32` underflows to NaN. |
| T3 | Defaults `iaf_cond_exp` `RK(4, 2)`, `aeif_cond_alpha` `RK(4, 16)`. G5 for spiking `aeif_cond_alpha` restated (option a1): spike times equal + CAT_A off the spike steps; in-substep threshold localisation deferred to K1. |
| T4 | All connectivity decisions on global ids; views must not contain duplicate gids; `fixed_total_number` refuses `allow_multapses=False`. |
| T5 | `Event -> Current/Conductance` allowed into `filtered` ports; `poisson_generator` fast path under `lax.cond(all(lam < 10))` (changed in T10, below); `Network` plain class, `Plan` the `brainstate` module; fresh models per `compile()`. |
| T6 | Plastic weights per-edge CSR only (Dense rejected: lossy multapse round trip); NEST lazy timing with the axonal/dendritic delay split; fast brainevent path (forward only) vs differentiable reference path; K0 restrictions: scalar delay, no trainable plastic weights, event sources only. |
| T7 | `iaf_psc_exp_ps` with a fixed 40-iteration Illinois root finder in one `lax.scan`, implicit-function spike-time gradients; `timed_event` capacity overflow is counted, never silent (`strict_capacity`). |
| T8 | Generic gated conductance ports (`with_conductance_ports`, `MgBlock` evaluated per RK substep); NMDA kinetics as a pre-aligned receptor population with explicit units. |
| T9 | G6 checked where BPTT is the exact derivative (hard forward feed-forward + detached reset + membrane loss; `relaxed_spikes()` for recurrent nets) — accepted by the orchestrator and written into spec §6; braintrace compatibility rules enforced by a checker. |
| T10 | Storage structure arrays (CSR `indices` / gather `rows`, Dense `mask`) are **arguments** of the compiled runner, not closed-over HLO constants (compile time and memory were proportional to the edges); `one_to_one` / small CSR use a gather/scatter path instead of brainevent; `poisson_counts` draws by CDF inversion (one uniform per element, 12 unrolled terms + `while_loop` tail) for `lam < 10` — exact in distribution (chi-square tested), no longer bit-identical to `jax.random.poisson`, which stays the `lam >= 10` branch. G2 discards a 100 ms transient (synchronous onset from `V_m = 0`); G3 uses no transient (random initial `V`). G9 protocol (user decision): CPU only, interleaved old/new on one idle pinned core, no load gate; GPU skipped. |

## 7. K1 follow-ups

1. In-substep threshold localisation for RK models (restores higher order for spiking
   `aeif_cond_alpha`; T3 option b).
2. NMDA kinetics folded into `SynapseModel` (today a receptor population, T8).
3. Traced / per-neuron gate parameters (`MgBlock` constants are static floats, T8).
4. Online learning: batching, delayed inputs as proper traces, a training loop (T9).
5. Timed sources with synapse models and plasticity (`timed_event` is event-only, T7).
6. T9 external inputs into timed ports.
7. Trainable plastic weights (hybrid L4), per-edge delays on plastic projections (T6).
8. `poisson_generator` `while_loop` tail: per-step cost depends on the largest draw;
   consider a fixed-depth table for `lam < 10`.
9. Dense multapse round trip (plastic Dense rejected today, T6).
10. Python-unrolled RK substeps: compile time grows with `k` (7.8 s at 16, 52 s at 32;
    T3); move substeps into a `fori_loop` / `scan`.
11. Spike-time gradients through timed delivery (EventProp-style, T7).
12. Episodes always start from step 0 in BPTT (no carried-over state, T9).
13. Done in T10 (was a follow-up): `one_to_one` fast path.
