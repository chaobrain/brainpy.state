## 1. Positioning

> **brainpy.state is a differentiable point-neuron modeling substrate: the same neurons,
> synapses, plasticity rules, and projections run NEST-validated biological simulation
> *and* train with gradients or online learning.**

- **Differentiator.** NEST is trusted but neither differentiable nor JIT-compiled to
  accelerators; SNN-training libraries are differentiable but carry no biological
  validation. brainpy.state aims to be the one substrate that is both
  *NEST-validated* and *end-to-end differentiable under XLA*.
- **Users, in priority order.**
  1. Computational neuroscientists moving NEST models to GPU/TPU, or training them.
  2. Brain-inspired-computing researchers who need biologically constrained SNNs.
  3. BrainX libraries built on top (e.g. `braintrace` for e-prop / online learning).
- **Non-goals.** Detailed multi-compartment morphology; MPI cluster-scale distributed
  simulation; MUSIC / SONATA co-simulation; e-prop itself (lives in `braintrace`).

## 2. Two families, one kernel — which way to lean

Decision: **shared kernel, two front-ends; the kernel leans toward the BrainPy style.**

| | BrainPy style (Module + State + projections) | NEST style (`Simulator`) |
|---|---|---|
| Extensibility | New model = subclass `Neuron`/`Synapse`; users can do it | New models often need special cases in `simulator.py` (1883 lines: alias table `:151-187`, receptor bridge `:1486`, rate/gap/sic paths) |
| Differentiable / composable | Native: nests in any `brainstate.nn.Module`, `for_loop`, `grad` | Closed kernel; hard to embed in a training loop |
| Ease of first use | Manual projection wiring | `create / connect / simulate` — friendly ✅ |
| Consistency | One `update(x)` + `add_*_input` | ~6 receptor-input conventions (`spike_events`, `w_by_rec`, `receptor_weights`, `x_filtered`, …); `i_syn_ex` vs `I_syn_ex` |

So: the BrainPy-style protocol is the *kernel* (extensible, differentiable); NEST
vocabulary is a *front-end* (approachable). Every NEST model implements the unified
protocol, `Simulator` and `Builder/Network` lower to the same Module graph, and a NEST
model can be dropped straight into `AlignPostProj` for training. The current three
entry points (bare BrainPy style, `Network/Builder`, `Simulator`) converge to two;
where `Builder` lands is decided in the Phase-1 spec.

### Phase 1 — v0.2: unified kernel (API unification & stability)

1. **Unified neuron protocol.** One receptor-input convention; `I_syn_*` naming plus a
   NEST-style `V_m` alias; every model declares `recordables`; delete the simulator's
   alias table and per-family special cases.
2. **Migrate host-object connections** (gap, rate, diffusion, sic) from
   `get_status/set_status` objects to the `edge_state_init/update` protocol.
3. **Make host-only models explicit.** The 4 `*_ps` models, `gif_pop_psc_exp`, and the
   NumPy-loop generators (`ppd_sup`, `gamma_sup`, `poisson_generator_ps`,
   `pulsepacket`) get a traceable JAX path or a `host_only` flag with a clear
   `Simulator` error. Fix `pp_cond_exp_mc_urbanczik` silently skipping its plasticity
   history under tracing (`:1129-1139`).
4. **Front-end convergence.** `Simulator` and `Builder/Network` lower to one Module
   graph; NEST models usable in `AlignPostProj`/`CurrentProj`.
5. **BrainPy-style de-duplication.** Shared `get_spike` + refractory mixin (~13 copies
   in `lif.py`); merge the duplicated scatter code in `synaptic_projection.py`; honour
   `spk_reset` in HH/MorrisLecar/WangBuzsakiHH/Izhikevich/reduced; fix the
   `(V - V_th)/V_th` sign flip when `V_th < 0`; make AMPA/GABAa/BioNMDA/Alpha
   `AlignPost`-mergeable; remove the empty `align_pre_ltp`/`align_post_ltp` stubs.
6. **Public-API freeze list.** Mark each of the 212 symbols stable / experimental and
   complete the NumPy docstrings (24 exports missing sections).

### Phase 2 — v0.2: scale & performance

- Sparse by default: choose `comm` by size; sparse graded emission for rate / gap /
  sic / diffusion (today `comm='sparse'` raises for these).
- Vectorised connection building: replace the per-neuron Python loop in
  `fixed_indegree/outdegree` (`connectivity.py:115-171`); blocked sampling for
  `pairwise_bernoulli` and the spatial rule instead of a full `(n_pre, n_post)` draw.
- Per-edge and distributed delays; expose `fixed_outdegree`,
  `symmetric_pairwise_bernoulli`, `pairwise_poisson` in `Simulator`.
- Sparse spike recording instead of dense `(T, n)` taps; `record_weight` without a
  full `(T, E)` stack.
- `Simulator(dt=)` must not mutate global `brainstate.environ`.
- Benchmark suite: Brunel and the Potjans–Diesmann microcircuit at 1e3–1e6 neurons —
  compile time, step time, memory — against NEST / NEST-GPU, tracked in CI.
- (Optional) multi-device sharding prototype via `shard_map`.

### Phase 3 — v0.2: learnability & plasticity rules

- Differentiable NEST family: surrogate-spike switch for NEST neurons; prove `grad`
  through a `Simulator` rollout (with `checkpointed_for_loop`).
- Plasticity: per-connection parameters (lift the scalar-only
  `_nest_base/plastic_base.py::to_scalar_float`), making `_hom` vs non-`_hom` real;
  learnable rule parameters (meta-plasticity); STDP and three-factor rules for the
  BrainPy-style family sharing one rule implementation with the NEST family.
- `braintrace` integration contract + examples (e-prop stays in `braintrace`).
- Add `parrot_neuron_ps`.
- Live-NEST parity for models with none today: `erfc_neuron`, `ht_neuron`,
  `iaf_bw_2001_exact`, `iaf_chs_2007`, `iaf_psc_alpha_multisynapse`,
  `iaf_psc_delta_ps`, `iaf_psc_exp_htum`, `iaf_psc_exp_ps_lossless`,
  `rate_transformer_node`, `static_synapse_hom_w`; precise-timing parity for all
  four `*_ps` models.
- Gap junctions: document or implement NEST's WFR (`use_wfr=True`) vs the current
  one-step lag; same for `siegert_neuron`.

### Phase 4 — declarative model spec (evaluate first)

A spec-only evaluation (no code) of the unmerged `spec` branch (20 commits, ~11k lines:
AST / string DSL / IR, validation + compile passes, clock-driven runtime, training
backends, `OpaqueModelSpec` bridge) against current `main`. Question: can it be the
description layer above the Phase-1 unified protocol? Outcome: merge, rewrite, or
archive, which decides whether it enters v0.3.

### 1.0 criteria

- Frozen public API with a deprecation policy (warnings for ≥ 2 minor releases).
- Every NEST model has live-NEST parity or a written exemption.
- > 90 % coverage; docs, doctests, and examples run in CI.
- Published benchmark report and migration guide.
